# Clutch

A lightweight macOS menu-bar app for Caps-based application shortcuts.

Clutch was previously named HyperCaps, and before that HyperKey. Its application bundle and signing identifier are `local.maxvoid.Clutch`; all internal identifiers use the same prefix. Settings saved by the older apps are not imported.

- Press and release Caps alone to send one short Caps press to macOS, which switches input sources. Clutch does not choose or remember input sources. Clutch does not manage Caps Lock: holding Caps never turns it on. To use Caps Lock, disable Clutch, which restores the Caps key. Caps held alone shows no HUD. While Caps is held, the first three keys pressed appear in the Caps pill (a small HUD in the upper part of the screen, where Spotlight's field sits) after ⇪, centered (for example “⇪ M W”); later keys are not shown. When the keys select an app, the pill becomes the app card in the same place: the keys on top in the normal text color, the app's icon and name below; the launch confirmation continues in that card. Once a hold starts with a window action key, the pill and card stay hidden until Caps is released: the window preview is the feedback. Gaps between ⇪ and each key are equal. The key pill, app card and launch confirmation share the same 14-point corner radius and blur mask. Escape while Caps is held cancels the gesture at once: the pill and card disappear, nothing runs on release, and the Escape press is not passed to the app. Return (or Enter) while Caps is held confirms: it runs at once what releasing Caps would run (an app, folder or website shortcut, or the window preview), then the pill and card disappear and nothing more runs on release. Return is never part of a shortcut. The pill and the app hint appear without fading in. The pill is not shown while the Folders panel is open. Gestures with Control, Option, or Command show no key hint. Releasing a key or modifier that was already down before Caps (for example, the last letter or Shift while typing quickly) does not cancel this press; pressing another key or modifier while Caps is held does. Native input switching and indicator behavior require desktop verification.
- Hold Caps and press Space to open Folders immediately, without switching input sources. The panel is one window with the search field across its top, placed where the Caps pill was; the pill disappears as it opens. The search field has focus; the preselected folder keeps its accent-colored highlight. While Caps is still held, letters jump to the best matching folder without editing the search field, filtering or reordering the list; nearby letters refine the jump, including pinyin. Releasing Caps opens the selected folder. After Caps is released, typing in an open panel filters the list by folder name (not path), ignoring case and accents, best match first: names with a word starting with the search, then names whose word initials spell it (“pd” → Project Docs), then names containing it. Chinese names also match by pinyin, one syllable per word (“wenjian”, “jian” or “wjj” find 文件夹), ignoring the input method's spaces and apostrophes, and text still being composed in an input method (Pinyin before a character is chosen) filters as you type. The first match is selected, so releasing Caps or pressing Return opens it. ↑/↓ move the selection without leaving the field, Escape clears the search (and closes the panel when the search is empty), and typing after clicking the list goes to the field. Caps + 1–9 select among the folders shown. Dragging to reorder works only while nothing is filtered, and each opening starts a new search. The Space press, its repeats, and its release are consumed, so no space is typed, and repeats do not reopen the panel. Space opens Folders whenever it is pressed during the hold, even after other keys: it takes over from an app shortcut or window preview started before it, so nothing else runs on release. Holding Control, Option, or Command, or pressing Escape first, blocks it (Space is consumed without opening Folders). Caps + Command no longer opens Folders. Keys pressed after opening pass through to the panel. The Folders panel uses a native rounded window style, with 6-point top padding and the same bottom controls as Preferences and no visible title or traffic-light buttons; drag its background to move it. Use + to add a folder: the same sheet as Add Website, with a Name (optional; empty uses the folder’s own name) and a Location, typed or picked with Choose…; a folder already listed is selected instead. − removes the selected entries from the list. Shift-click selects a range, Command-click toggles individual entries, and Command-A selects all. Right-click an entry (which selects it) and choose Edit… to change its name and location in the same sheet as Add (Choose… picks the folder), like a website's name and URL; leaving the name empty uses the folder’s own name. The location must be an existing folder not already listed (“~” works); the shortcut stays, and an entry still showing its folder’s own name takes the new folder’s name. Restore Original Name puts every selected renamed entry back to the name Finder shows. The actual folder on disk is never renamed. Double-click or press Return to open all selected entries in Finder. Missing folders and folders that fail to open are skipped; failures are reported together after the remaining entries have been attempted. While holding Caps, type a number or letter or use the arrow keys to select without editing the search, then release Caps to open the selection. Opening with Caps + Space and releasing the keys without further selection input leaves the panel open, regardless of release order. Releasing a Caps navigation chord does not switch input sources; standalone Caps sends the same press to macOS in every context. Caps-held navigation keys pass through to the list. Drag selected rows to reorder them together. Holding the mouse button and sweeping across rows does not extend the selection; use Shift-click or Command-click to select multiple rows. The panel and Preferences share the same folder row layout and selection styling. Neither shows paths in the rows: pointing at a folder shows its path, starting with ~ inside your home folder. Right-click a folder for Open, Edit…, Restore Original Name and Reveal in Finder. Selection styling: inset highlights connect adjacent selected rows, with rounded corners only at each group’s ends. App List uses this same selection styling, and all Preferences pages share the panel’s background surface. Preferences adds Name and Shortcut headings. Preferences headers sit outside their scroll views, keeping the separator full-width when scrollbars appear. Columns use fixed widths, with no automatic resizing or draggable header dividers, matching Mos. Preferences reserves a permanent scrollbar allowance. The Folders panel instead fits its columns to the available viewport, reclaiming that space when the scrollbar is hidden. Shortcut headings stay left-aligned while each shortcut control group aligns to its column’s right edge. The first nine panel rows always show an inline ⇪ numbered shortcut at the right; Caps Lock-1 through Caps Lock-9 select and scroll to the corresponding folder in the current order. While holding Caps Lock, change the selection with another number, by typing a search, or with the arrow keys. Command is ignored for Caps-held list navigation. Normal Command shortcuts remain available after releasing Caps Lock. Arrow keys also select entries; Escape or Command-W cancels the list and restores focus to the application/window active before opening it. Clicking outside closes the list and keeps focus on the clicked window. Opening Folders alone does not add a Dock icon. Folder paths, display names, and order are saved across restarts. Folders… is also available in the menu while Clutch is disabled.
- Caps + an assigned key activates a running application when Caps is released. Window cycling applies to every App List mapping, including newly added apps and reassigned keys. If the mapped app is already frontmost, each Caps + key cycles to its next non-minimized standard window, wrapping after the last window. For example, Caps Lock + F brings Finder forward; release Caps and press Caps + F again to switch to Finder’s next window. Window cycling uses Accessibility; apps that do not expose standard windows stay focused without switching. In Finder, clicking the desktop moves focus to the desktop, which is not one of Finder’s windows; Caps + F then brings back the frontmost Finder window, and later presses cycle as usual. The desktop itself is never part of the cycle. If the running app has no open, non-minimized standard window (for example after closing its last window, or when every window is minimized), Clutch reopens it the way clicking its Dock icon does, so Finder, Safari, Terminal and similar apps open a new window and AppKit apps restore a minimized one instead of only switching the menu bar. While Caps is held, the Caps pill becomes a card showing the keys, and the icon and name of the app that releasing Caps would open. With no matching app, the key pill extends downward to say “No matching app”, keeping the shortcut row in its original screen position; shortcut text uses the normal text color in both states. If that app is not running, releasing Caps keeps the HUD on screen as the launch confirmation, in two stages within the same window size: the icon shrinks slightly with the app name moving up beneath it, and small gray “⎋ Cancel” and “↩ Open” labels fade in at the bottom-left and bottom-right corners. There are no buttons. Whether the app is running is checked again on release. Escape or Command-W cancels and restores focus to the previously active application, and Return opens it. Clicking outside dismisses the prompt without changing the clicked application’s focus. The shortcut and its repeat/release events are consumed; unassigned keys are consumed while Caps is held. Shortcuts of two or three keys work the same way: hold Caps, press the keys in order (for example Caps + M + W opens Word, Caps + M + W + E opens Excel). Only Caps has to stay held: each key can be tapped and released before the next. Order matters (M + W and W + M are different shortcuts). Keys may repeat (Caps + M + M). Shortcuts run when Caps is released, so Caps + M, Caps + M + W and Caps + M + W + E can belong to different apps: releasing Caps after M alone opens the first, after M then W the second, after M, W, E the third. The keys must match a shortcut exactly: pressing the same key again in one hold only counts as Caps + M + M (if that is a shortcut), so Caps + C + C does not run Caps + C, and Caps + C + C + L does not run Caps + C + L. All keys pressed while Caps is held, including unassigned keys and modifier changes, are consumed together with their repeats and releases, so the original app receives no chord input. Clutch’s own Folders panel and focused editors still receive their input. An unassigned first key invalidates the whole app shortcut: Caps + A + C cannot run Caps + C. A key that neither completes nor continues a shortcut means nothing runs. Only the first three keys count: keys pressed after the third are ignored, so Caps + M + W + E + R still runs Caps + M + W + E. Window actions keep precedence, so a window action key cannot start a multi-key shortcut.
- Caps + a website's shortcut goes to that website in the default browser when Caps is released. While Caps is held, the HUD card shows it like an app or folder: the keys on top, the default browser's icon and the website's name below; there is no launch confirmation. In Safari, Safari Technology Preview and Chromium browsers (Chrome, Edge, Brave, Vivaldi, Chromium), an already open tab of the website is selected and its window brought forward, restoring it if minimized; pressing the shortcut again while that tab is in front goes to the next matching tab, in a fixed order across windows, wrapping after the last. When no tab matches, the browser is not running, or it is another browser (Firefox, Arc and others cannot list their tabs), the HUD asks first, like an app that is not running: the card shows the website with “⎋ Cancel” and “↩ Open”, and Return opens the address in a new tab. The card stays on screen after Caps is released while the open tabs are looked up, so the confirmation continues the same card, and it disappears once a matching tab is in front. A website saved as a domain (github.com) matches every page of that site, with or without www. With Include subdomains (on unless turned off), it also matches subdomains such as gist.github.com; localhost and IP addresses have none. A tab that another saved website inside it matches (flight.ctrip.com, or github.com/you/project, saved with its own shortcut) belongs to that website, so the wider one leaves it alone. Among the remaining matches, a tab on the site’s own domain comes before its subdomains. Saved with a path (github.com/qianshuguo/clutch), it matches that page and the pages below it, not siblings such as github.com/qianshuguo/clutchy. Matching ignores http/https, letter case in the path, trailing slashes, queries and fragments. Like a browser bookmark, a website has a name and an address. The list shows the name (a website without a name shows what it matches instead); pointing at a website shows its full address. The Websites name column runs up to the shortcut field to give names more room; pointing at one shows the full address it opens. The HUD card and launch confirmation show the name. Seeing the tabs uses Apple Events: the first time, macOS asks to let Clutch control the browser. If that is turned off under System Settings › Privacy & Security › Automation, the shortcut asks to open a new tab, and after opening one Clutch explains why once per launch. A browser that does not answer within 3 seconds is treated as having no matching tab.
- On first launch, the App List starts with Finder (Caps + F), Notes (Caps + N), Preview (Caps + P) and Reminders (Caps + R), and Folders starts with Downloads, Desktop, Documents and Applications (Caps + 1–4). Apps or folders that are missing on the Mac are skipped. Once either list has been changed and saved, its defaults are no longer applied, even if it is emptied.
- Caps + arrow keys, −, = and / arrange the focused window of the frontmost application, following Rectangle's layouts. While Caps is held, a preview shows where the window will go (a translucent accent-colored rectangle with a border, like Rectangle's footprint); releasing Caps moves the window there in one step. Caps + ← / → snaps it to the left / right half of its display's visible area (below the menu bar, beside the Dock); pressing the same arrow again, while still holding Caps or later while the window is still where Clutch put it, cycles 1/2 → 2/3 → 1/3. Caps + ↑ keeps the window's position and width and fills the display's height; Caps + ↑ on a window that already spans top to bottom (after Caps + ↑, a half-screen layout, or resizing by hand) maximizes it to the whole visible area (this is not macOS full-screen mode), and Caps + ↑ on a window Clutch maximized returns it to full height at its previous width, so repeated presses toggle between the two. Caps + ↓ restores the frame the window had before its first Clutch layout. Caps + / centers the window on its display, keeping its size. Caps + − / = shrinks / grows the window by 30 points in each direction, keeping its center or any edge already touching the screen; growing stays on screen, and shrinking stops at a quarter of the display. While Caps is held, each press steps the preview (− / = add one size step per press), another window key starts over as if only that key had been pressed (so ← then ↑ previews ↑ on the original window), and Escape or any other key cancels it; nothing moves until Caps is released. Holding a key does not repeat. Moving or resizing the window by hand starts a new sequence and a new restore point. Windows in native full-screen mode and Clutch's own windows are left alone. These are the default keys; each can be changed on the Windows page of Preferences. A key belongs either to one window action or to apps (alone or as the first key of two-key shortcuts). In the Folders panel, arrows still navigate the list. Layout uses Accessibility off the main thread. Each layout writes only the size or position that actually changes, in an order whose in-between frame stays on screen, so the window redraws once or twice instead of three times; a corrective write follows only if the app did not land on the target. Apps that refuse a size (fixed-size windows, terminal grids) keep their nearest supported size.
- Clutch's Edit menu gives text fields Cut, Copy, Paste, Select All, Undo and Redo (⌘X, ⌘C, ⌘V, ⌘A, ⌘Z, ⇧⌘Z).
- Command-S toggles Clutch while its menu or settings are active. It does not override Save in other applications. Command-W closes Settings, including while a shortcut is being recorded.

## Settings

Scrollable lists use standard AppKit scroll views and scrollbars with plain table rows, as in Mos 3.5.0. Row margins and column widths stay fixed when the system switches between overlay and always-visible scrollbars. Tables, clip views, and scroll views reveal one shared active, behind-window tooltip-material backdrop, matching Mos’s transparent list structure. macOS manages scrollbar appearance, layout, and fading according to System Settings > Appearance > Show scroll bars. Scrollbars hide when the content fits. There is no custom thumb drawing or forced scrollbar style.

Preferences uses a fixed content size of 460 × 311 points (exactly the seven Windows rows, without scrolling), with close-only window controls and no resizing or full-screen mode, matching Mos’s window strategy. AppKit handles display scaling. It has five toolbar pages: General, App List, Folders, Websites, and Windows. There is no separate tutorial page: App List, Folders, Websites, and Windows each have a native round ? help button in their bottom bar. Clicking it shows a small two-column popover, as in Mos: what to press on the left, what it does on the right; clicking again, clicking elsewhere, or Escape closes it. Folders manages the same saved list as the Caps + Space panel, including adding, removing, editing names, restoring original names, multiple selection, opening, and drag reordering. Its list shows folder names with the same shortcut fields as App List. A folder shortcut (one to three keys, for example ⇪D W) opens the folder in Finder from any app when Caps is released, and while Caps is held the HUD card shows the folder. App, folder and website shortcuts share one set of keys: taking one from another asks first, and window action keys take precedence as the first key. Websites lists websites with the same shortcut fields. Use + to add one: a sheet asks for a Name (optional; gray text shows the address an empty name shows) and a URL; type or paste the address (github.com, or github.com/you/project for just that part of the site). Include subdomains under the URL is checked for a new website. Adding an address already listed selects it. Double-click a website or press Return to open the selected websites, like folders: an open tab of each is brought forward, otherwise it opens in a new tab, without asking first. Right-click a website (which selects it) for Open and Edit…; Edit… changes its name, URL and Include subdomains, and its shortcut stays. An address another website already has is refused, and that website is selected. − removes the selected websites; Shift-click, Command-click and Command-A select several. General contains checkboxes for Enable Clutch, Launch on Login, and Hide Status Bar Icon. Enabling without Accessibility permission first requests the system authorization prompt. General shows a gray, underlined “Waiting for Accessibility access” link while permission is still missing; click it to open Accessibility settings. The notice disappears after permission is granted or enabling is cancelled. Reopen Clutch to show Preferences when its menu-bar icon is hidden. Login launch uses the system login-item service on macOS 13 and later, and a user LaunchAgent on macOS 12. Set this after moving the app to its permanent location.

App List shows applications on the left and a clickable shortcut field on the right, styled like Rectangle's: a round-rect field with the shortcut centered, Caps written as ⇪ (for example “⇪M W”), “Record Shortcut” when empty, and ✕ at its right edge to clear the shortcut (the app stays in the list). Use + to add an application and − to remove all selected applications. Shift-click selects a range, Command-click toggles individual applications, and Command-A selects all. The search field in the bottom bar (Command-F) filters the list as you type: an application is shown when its name contains the text, or when its shortcut starts with the keys typed, written any common way (“M W”, “m+w”, “Caps + M + W” and “mw” all find Caps + M + W; “M” finds every shortcut starting with M). Down or Return moves into the results, and Escape clears the search (with nothing to clear, Escape closes Preferences as before). When nothing matches, the list says so. Adding, removing and selecting work on the rows shown; adding an application, or choosing one already in the list, clears a search that would hide it. With the list focused, typing a name jumps to that application; shortcut fields take no part in this. Click a shortcut field, then enter the shortcut exactly as you use it: hold Caps, press one to three keys in order (for example M then W), and release Caps (or press Return while still holding Caps) to save it. The field responds as you type: “⇪…” when Caps goes down, then “⇪M…”, “⇪M W…” and “⇪M W E”. Releasing Caps without another key records nothing, and while a field is recording Caps does not toggle Caps Lock. While recording, the field is pressed in, shows “Hold ⇪ to start…”, and has ⎋ at its right edge to cancel (pointing at it shows “Cancel” or “Use Old Shortcut”); keys pressed without Caps are not recorded. Recording needs Clutch to be enabled, since it reads Caps through the same keyboard monitor; while Clutch is off the field shows “Turn on Clutch”. Keys may repeat (Caps + M + M); none can be Space, Delete or Return. Command-click or Shift-click on a shortcut field selects rows using the same multi-selection behavior as the rest of the list. Escape cancels. Space is reserved for Caps + Space (Folders) and cannot be assigned. Assigning a shortcut already in use asks for confirmation and names who would lose it, for example “⇪M W already opens Excel. To use ⇪M W for Word, Excel will lose its shortcut.” Choose Replace or press Enter to transfer it to the selected application; the previous application stays in the list with its shortcut cleared to “Record Shortcut”. Choose Cancel or press Esc to keep all assignments unchanged. Windows uses the App List layout: window actions (Left Half, Right Half, Fill Height · again: Full, Restore, Make Smaller, Make Larger, Center) on the left and the same shortcut field (for example “⇪←”) on the right. Hover over an action for a full description. Click a field, hold Caps, press a key, and release Caps (the field shows “Hold ⇪ to start…”); Escape or ⎋ cancels, and ✕ clears an action's shortcut. Space is reserved for Folders. A key already used by an app or another action asks for confirmation, and the previous owner stays in its list with “Record Shortcut”. Shortcuts are saved across restarts. Restore Defaults brings back ←, →, ↑, ↓, −, = and /, and asks first if that would take a key from an app. All interface labels are in English.

While Preferences is open, Clutch appears in the Dock and Command-Tab. Pressing Caps alone sends the system Caps Lock event without closing Preferences or its chooser sheets. Activating an assigned application or opening the Folders panel automatically closes Preferences. When Folders or an application launch confirmation takes over from Preferences, the Dock icon stays until that panel closes, avoiding a focus change that would dismiss the new panel. Closing Preferences with the close button, Escape, or Command-W hides the Dock icon once no action panel remains and keeps shortcuts running in the background. Open Settings from the ⇪+ menu or reopen Clutch to bring the window and Dock icon back. Quit Clutch (Command-Q) exits the app.

The window is created on demand and released when closed. The app uses one keyboard event tap, with no continuous polling. Authorization polling runs only while waiting for Accessibility access. If macOS pauses the tap because a callback was late, Clutch resumes it immediately. Secure Event Input (password fields, Terminal’s Secure Keyboard Entry) hides key releases from event taps; after such a quiet period Clutch checks the hardware key state once, so a hidden release can neither leave a key swallowed nor turn ordinary typing into Caps shortcuts. Window-cycling Accessibility calls run off the main thread, and hidutil runs only while the tap is not installed. Saved shortcut or folder lists that cannot be read are kept under `Bindings.unreadable` / `Folders.unreadable` and reported instead of being overwritten. If Caps Lock cannot be restored on quit, Clutch offers Quit Anyway. Control + Caps and Option + Caps have no action and do not switch input sources.

Enable Clutch from the ⇪+ menu and allow it under System Settings > Privacy & Security > Accessibility. A rebuilt local app may need to be removed and added to the permission list again, because ad-hoc signatures change on every build. To keep the permission across rebuilds, create a Code Signing certificate once in Keychain Access (Certificate Assistant > Create a Certificate…) and build with `CLUTCH_SIGN_IDENTITY="<certificate name>" ./build.command`.

While enabled, Caps is temporarily mapped to F18; a physical F18 key has the same effect. Pause, exit and sleep restore the previous mapping. Reopen after a crash, or reboot, to recover. Other keyboard remappers or secure-input contexts may interfere.

Run build.command for a locally signed arm64 + x86_64 application (macOS 12+). Run test.command for routing and mapping recovery checks. Real keyboard/indicator behavior still requires authorized desktop testing.

### Investigating native Caps compatibility

Standalone Caps uses one shared state-machine rule in every context, including Folders selection and editing, shortcut recording, and launch confirmation. Context controls only chord actions: app shortcuts and Caps + Space are suppressed in focused editors, recording, and confirmation; folder navigation applies only to the selection list. Focus changes preserve standalone Caps while cancelling pending chord actions and retaining swallowed key releases. The original report referred to Clutch's Folders panel, not macOS Finder: the editor previously swallowed Caps without replaying it. Standalone Caps is sent to macOS as one short press. Passing routing/encoding tests does not establish full native input-source, indicator, or Caps Lock compatibility.

Run `./diagnose-caps.command` in Terminal to observe the event path for 90 seconds (Control-C stops early). If observation is denied, grant that terminal Input Monitoring access and rerun. With Clutch disabled, open its Folders panel from the menu, select Chinese, choose Edit… on an entry, and tap Caps in its name field; cancel the sheet. Enable Clutch and repeat the same sequence starting in Chinese. Also compare a held Caps press in each mode. Save the Terminal output for diagnosis. The tool reports Caps/F18 events at HID and session observation points, modifier flags, frontmost application identifiers, and input-source changes. It does not record typed characters or file names and does not post events or modify mappings. `./diagnose-caps.command --self-test` checks event filtering without starting observation.

## Xcode interface previews

Open `Clutch.xcodeproj` in Xcode 15.2 or later. Finish Xcode's first-launch license and component installation if prompted. Select the Clutch scheme and My Mac, then open `Source/Preferences/PreferencesPreview.swift`. Choose Editor > Canvas (Option-Command-Return), and click Resume if needed. Canvas offers General, App List, Folders, Websites, and Windows previews of the actual AppKit content. The native window toolbar is visible when running the app.

Edit `makePreferencesContent()` in `Source/Preferences/AppDelegate+Preferences.swift` to change the interface. Keep the preview file open in a split editor to see updates; Canvas may need Resume after compilation errors or pausing. Canvas includes a visual title bar and toolbar shell using the app's shared tab labels and symbols; macOS draws the native window chrome when the app runs. Previews only display the interface: they do not run application startup, change keyboard mappings, or handle clicks. App List reads existing bindings, falling back to installed example apps.

Use Command-R to test interactions in the real app; the shared scheme opens Settings automatically. Quit an already running Clutch first so its single-instance protection does not redirect to an older build. The existing `build.command` remains the release build path.

## Source layout

- `Source/main.swift`: application entry point only.
- `Source/App/`: shared coordinator state, application lifecycle, menus, and window focus/cleanup.
- `Source/Keyboard/`: event tap, keyboard gesture state, Caps mapping/recovery, and standalone Caps system-event replay.
- `Source/Applications/`: app bindings, shortcut recording, activation, and launch confirmation.
- `Source/Folders/`: folder models/order/batch opening, picker UI, and folder management.
- `Source/Websites/`: website models and matching (`WebsiteEntry`, `WebsiteAddress`, `WebsiteTabChoice`, Foundation-only and covered by the pure tests), browser tab listing and switching over Apple Events (`BrowserTabs`), the Websites page list, and adding, removing and opening websites.
- `Source/Preferences/`: settings window/pages, general options, and Xcode previews.
- `Source/Windows/`: Caps window layout (`WindowLayout` holds the pure geometry and repeat rules; `WindowManager` applies layouts through Accessibility; `WindowShortcutListController` is the Windows page list).
- `Source/Shared/`: reusable list styling and button callbacks, saved `WindowShortcuts`, persistence, and errors.

`AppDelegate` holds application data and coordinates keyboard and window behavior. `ApplicationListController` owns the application table; each folder view has its own `FolderListController` for rendering, selection, editing, and drag handling. Folder actions receive their source table explicitly rather than looking up the focused window. Shortcut lookup, conflicts, confirmation and assignment for App List, Folders, Websites and Windows live in one place, `AppDelegate+Bindings.swift` (`ShortcutOwner`, `assignShortcut`, `setShortcuts`); shared list code only handles layout and styling. Both the Xcode project and `build.command` compile these files. When adding a Swift source, add it to the Xcode target as well; the command-line build discovers files recursively. `test.command` checks the pure keyboard, mapping, and folder logic, then runs AppKit list checks without starting the utility or changing keyboard mappings.

Shared behavior is centralized in `failKeyboard` (failure cleanup/reporting), `PreviousFocus` (transient-panel focus restoration), `ListGeometry` (header/body placement), `FolderListPresentation` (picker versus preferences settings), and `ListSelection` (selection and deletion rules). Modal dismissal and outside-click handling remain owned by each panel.
