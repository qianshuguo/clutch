# Clutch

A lightweight macOS menu-bar app for Caps-based application shortcuts.

Clutch was previously named HyperCaps, and before that HyperKey. Its application bundle and signing identifier are `local.maxvoid.Clutch`; all internal identifiers use the same prefix. Settings saved by the older apps are not imported.

- Press and release Caps alone to send one short Caps press to macOS, which switches input sources. Clutch does not choose or remember input sources. Clutch does not manage Caps Lock: holding Caps never turns it on. To use Caps Lock, disable Clutch, which restores the Caps key. Caps held alone shows no HUD. While Caps is held, the first three keys pressed appear in the Caps pill (a small HUD in the upper part of the screen, where Spotlight's field sits) after ⇪, centered (for example “⇪ M W”); later keys are not shown. When the keys select an app, the pill becomes the app card in the same place: the keys on top in the normal text color, the app's icon and name below; the launch confirmation continues in that card. Once a hold starts with a window action key, the pill and card stay hidden until Caps is released: the window preview is the feedback. Gaps between ⇪ and each key are equal. The key pill, app card and launch confirmation share the same 14-point corner radius and blur mask. Escape while Caps is held cancels the gesture at once: the pill and card disappear, nothing runs on release, and the Escape press is not passed to the app. Return (or Enter) while Caps is held confirms: it runs at once what releasing Caps would run (an app, folder or website shortcut, or the window preview), then the pill and card disappear and nothing more runs on release. Return is never part of a shortcut. The pill and the app hint appear without fading in. Gestures with Control, Option, or Command show no key hint. Releasing a key or modifier that was already down before Caps (for example, the last letter or Shift while typing quickly) does not cancel this press; pressing another key or modifier while Caps is held does. Native input switching and indicator behavior require desktop verification.
- Caps + Space opens the Shelf: a picker for files you need for a while (an attachment to send, a download to read) without giving each its own shortcut. It opens as Space is pressed, even after other keys in the same hold (whatever they would have run is dropped), and its search field takes the Caps pill's place. Shelf… in the ⇪+ menu opens it too. Files are listed in your order, new files on top, with their icons; pointing at one shows its path. Typing filters the list by name, best match first: a word starting with the text, then word initials (“qr” finds “Q3 Report”), then any part of the name, ignoring case and accents; Chinese names also match by pinyin and its initials (“baogao”, “bg”), including text an input method is still composing. ↑/↓ move the selection, Return or double-click opens the selected files with their default apps, ⌘Return reveals them in Finder, and ⌘⌫ takes them off the Shelf (the files themselves are never touched); right-click offers the same. While Caps is held, 1–9 select the first nine rows (shown as ⇪1…⇪9), letters jump to a matching name, arrows move, and releasing Caps opens the selection; Caps alone still switches input sources. Like Spotlight, the Shelf takes the keyboard without making Clutch the active app: the app in front stays active, its window is not dimmed and its menu bar stays. Escape clears the search, or closes the Shelf and returns to the previous app; clicking elsewhere closes it too. To add files, copy them in Finder (⌘C), open the Shelf and press ⌘V, or drop files on it (press Caps + Space while dragging); a file already on the Shelf moves to the top. Drag rows within the list to reorder them (with the search empty), or out, for example into a mail or upload window. Opening a file does not change the order; the Shelf closes at once and the file's app comes forward when it is ready. Files stay on the Shelf until they are removed; only a file that was moved or deleted leaves by itself, when the Shelf next opens. The Shelf is saved across restarts. The Shelf has no Preferences page: everything is done in the Shelf itself. General has a line, “Caps + Space opens the Shelf”, with an Open Shelf button. Space cannot be assigned to a shortcut.
- Caps + Tab opens Preferences from anywhere, the same way: on press, and nothing else in that hold runs. There is no Command-Comma; the ⇪+ menu shows no shortcut for Preferences or Shelf… (macOS menus cannot show ⇪), and General names both: “Caps + Space opens the Shelf” and “Caps + Tab opens Preferences”. Tab cannot be assigned to a shortcut. Folders have no picker: give each folder its own shortcut on the Folders page of Preferences.
- Caps + an assigned key activates a running application when Caps is released. Window cycling applies to every App List mapping, including newly added apps and reassigned keys. If the mapped app is already frontmost, each Caps + key cycles to its next non-minimized standard window, wrapping after the last window. For example, Caps Lock + F brings Finder forward; release Caps and press Caps + F again to switch to Finder’s next window. Window cycling uses Accessibility; apps that do not expose standard windows stay focused without switching. In Finder, clicking the desktop moves focus to the desktop, which is not one of Finder’s windows; Caps + F then brings back the frontmost Finder window, and later presses cycle as usual. The desktop itself is never part of the cycle. If the running app has no open, non-minimized standard window (for example after closing its last window, or when every window is minimized), Clutch reopens it the way clicking its Dock icon does, so Finder, Safari, Terminal and similar apps open a new window and AppKit apps restore a minimized one instead of only switching the menu bar. While Caps is held, the Caps pill becomes a card showing the keys, and the icon and name of the app that releasing Caps would open. With no matching app, the key pill extends downward to say “No matching app”, keeping the shortcut row in its original screen position; shortcut text uses the normal text color in both states. If that app is not running, releasing Caps keeps the HUD on screen as the launch confirmation, in two stages within the same window size: the icon shrinks slightly with the app name moving up beneath it, and small gray “⎋ Cancel” and “↩ Open” labels fade in at the bottom-left and bottom-right corners. There are no buttons. Whether the app is running is checked again on release. Escape or Command-W cancels and restores focus to the previously active application, and Return opens it. Clicking outside dismisses the prompt without changing the clicked application’s focus. The shortcut and its repeat/release events are consumed; unassigned keys are consumed while Caps is held. Shortcuts of two or three keys work the same way: hold Caps, press the keys in order (for example Caps + M + W opens Word, Caps + M + W + E opens Excel). Only Caps has to stay held: each key can be tapped and released before the next. Order matters (M + W and W + M are different shortcuts). Keys may repeat (Caps + M + M). Shortcuts run when Caps is released, so Caps + M, Caps + M + W and Caps + M + W + E can belong to different apps: releasing Caps after M alone opens the first, after M then W the second, after M, W, E the third. The keys must match a shortcut exactly: pressing the same key again in one hold only counts as Caps + M + M (if that is a shortcut), so Caps + C + C does not run Caps + C, and Caps + C + C + L does not run Caps + C + L. All keys pressed while Caps is held, including unassigned keys and modifier changes, are consumed together with their repeats and releases, so the original app receives no chord input. Clutch’s own focused editors still receive their input. An unassigned first key invalidates the whole app shortcut: Caps + A + C cannot run Caps + C. A key that neither completes nor continues a shortcut means nothing runs. Only the first three keys count: keys pressed after the third are ignored, so Caps + M + W + E + R still runs Caps + M + W + E. Window actions keep precedence, so a window action key cannot start a multi-key shortcut.
- Caps + a website's shortcut goes to that website in the default browser when Caps is released. While Caps is held, the HUD card shows it like an app or folder: the keys on top, the default browser's icon and the website's name below. In Safari, Safari Technology Preview and Chromium browsers (Chrome, Edge, Brave, Vivaldi, Chromium), an already open tab of the website is selected and its window brought forward, restoring it if minimized; pressing the shortcut again while that tab is in front goes to the next matching tab, in a fixed order across windows, wrapping after the last. When no tab matches, the browser is not running, or it is another browser (Firefox, Arc and others cannot list their tabs), the HUD asks first (unless Ask Before Opening is off), like an app that is not running: the card shows the website with “⎋ Cancel” and “↩ Open”, and Return opens the address in a new tab. The card stays on screen after Caps is released while the open tabs are looked up, so the confirmation continues the same card, and it disappears once a matching tab is in front. A website saved as a domain (github.com) matches every page of that site, with or without www. With Include subdomains (on unless turned off), it also matches subdomains such as gist.github.com; localhost and IP addresses have none. A tab that another saved website inside it matches (flight.ctrip.com, or github.com/you/project, saved with its own shortcut) belongs to that website, so the wider one leaves it alone. Among the remaining matches, a tab on the site’s own domain comes before its subdomains. Saved with a path (github.com/qianshuguo/clutch), it matches that page and the pages below it, not siblings such as github.com/qianshuguo/clutchy. Matching ignores http/https, letter case in the path, trailing slashes, queries and fragments. Like a browser bookmark, a website has a name and an address. The list shows the name (a website without a name shows what it matches instead); pointing at a website shows its full address. The Websites name column runs up to the shortcut field to give names more room; pointing at one shows the full address it opens. The HUD card and launch confirmation show the name. Seeing the tabs uses Apple Events: the first time, macOS asks to let Clutch control the browser. If that is turned off under System Settings › Privacy & Security › Automation, the shortcut asks to open a new tab, and after opening one Clutch explains why once per launch. A browser that does not answer within 3 seconds is treated as having no matching tab. The events go to the running browser process itself, so a browser that has just quit is never relaunched by them (AppleScript would launch it again, and a Chrome still shutting down then reports that it could not open the profile).
- On first launch, the App List starts with Finder (Caps + F), Notes (Caps + N), Preview (Caps + P) and Reminders (Caps + R), and Folders starts with Downloads, Desktop, Documents and Applications, without shortcuts. Apps or folders that are missing on the Mac are skipped. Once either list has been changed and saved, its defaults are no longer applied, even if it is emptied.
- Caps + arrow keys, Delete, − and = arrange the focused window of the frontmost application, following Rectangle's layouts. While Caps is held, a preview shows where the window will go (a translucent accent-colored rectangle with a border, like Rectangle's footprint); releasing Caps moves the window there in one step. Caps + ← / → snaps it to the left / right half of its display's visible area (below the menu bar, beside the Dock); pressing the same arrow again, while still holding Caps or later while the window is still where Clutch put it, cycles 1/2 → 2/3 → 1/3. Caps + ↑ keeps the window's position and width and fills the display's height; Caps + ↑ on a window that already spans top to bottom (after Caps + ↑, a half-screen layout, or resizing by hand) maximizes it to the whole visible area (this is not macOS full-screen mode), and Caps + ↑ on a window Clutch maximized returns it to full height at its previous width, so repeated presses toggle between the two. Caps + Delete (⌫) restores the frame the window had before its first Clutch layout, as in Rectangle, exactly as it was, even partly off-screen or on another display; once an app shortcut has started, Delete still takes back its last key. Caps + ↓ centers the window on its display, keeping its size. Caps + − / = shrinks / grows the window by 30 points in each direction, keeping its center or any edge already touching the screen; growing stays on screen, and shrinking stops at a quarter of the display. While Caps is held, each press steps the preview (− / = add one size step per press), another window key starts over as if only that key had been pressed (so ← then ↑ previews ↑ on the original window), and Escape or any other key cancels it; nothing moves until Caps is released. Holding a key does not repeat. Moving or resizing the window by hand starts a new sequence and a new restore point. Windows in native full-screen mode and Clutch's own windows are left alone. These are the default keys; each can be changed on the Windows page of Preferences. A key belongs either to one window action or to apps (alone or as the first key of two-key shortcuts). Layout uses Accessibility off the main thread. Each layout writes only the size or position that actually changes, in an order whose in-between frame stays on screen, so the window redraws once or twice instead of three times; Apps that refuse a size (fixed-size windows, terminal grids, minimum sizes) keep the size they chose, as in Rectangle: Clutch does not ask for it again (except once after a move, which can lift a limit) and instead moves the window to the screen edges the layout touches, so a terminal snapped to the right half ends exactly at the right edge; a layout touching both edges of an axis, or neither, centers it there instead, and it stays on screen. Restore is not aligned or kept on screen. A shortfall of one point is left alone.
- Clutch's Edit menu gives text fields Cut, Copy, Paste, Select All, Undo and Redo (⌘X, ⌘C, ⌘V, ⌘A, ⌘Z, ⇧⌘Z).
- Command-S toggles Clutch while its menu or Preferences is active. It does not override Save in other applications. Command-W closes Preferences, including while a shortcut is being recorded.

## Preferences

Scrollable lists use standard AppKit scroll views and scrollbars with plain table rows, as in Mos 3.5.0. Row margins and column widths stay fixed when the system switches between overlay and always-visible scrollbars. Tables, clip views, and scroll views reveal one shared active, behind-window tooltip-material backdrop, matching Mos’s transparent list structure. macOS manages scrollbar appearance, layout, and fading according to System Settings > Appearance > Show scroll bars. Scrollbars hide when the content fits. There is no custom thumb drawing or forced scrollbar style.

Preferences uses a fixed content size of 460 × 345 points (the seven Windows rows without scrolling, plus one row of room so General is not crowded), with close-only window controls and no resizing or full-screen mode, matching Mos’s window strategy. AppKit handles display scaling. It has five toolbar pages: General, App List, Folders, Websites, and Windows. There is no separate tutorial page: App List, Folders, Websites, and Windows each have a native round ? help button in their bottom bar. Clicking it shows a small two-column popover, as in Mos: what to press on the left, what it does on the right; clicking again, clicking elsewhere, or Escape closes it. Folders lists folder names with the same shortcut fields as App List; neither the rows nor the list show paths, and pointing at a folder shows its path, starting with ~ inside your home folder. Use + to add a folder: the same sheet as Add Website, with a Name (optional; empty uses the folder’s own name) and a Location, typed or picked with Choose…; a folder already listed is selected instead. − removes the selected entries; Shift-click, Command-click and Command-A select several, and dragging selected rows reorders them together. Double-click a folder, or right-click it (which selects it) and choose Edit…, to change its name and location in the same sheet; the location must be an existing folder not already listed (“~” works), the shortcut stays, and an entry still showing its folder’s own name takes the new folder’s name. The folder on disk is never renamed. Return or the menu’s Open opens all selected folders in Finder; missing folders and folders that fail to open are skipped and reported together. Right-click also offers Reveal in Finder. Folder paths, display names, shortcuts and order are saved across restarts. A folder shortcut (one to three keys, for example ⇪D W) opens the folder in Finder from any app when Caps is released, and while Caps is held the HUD card shows the folder. App, folder and website shortcuts share one set of keys: taking one from another asks first, and window action keys take precedence as the first key. Websites lists websites with the same shortcut fields. Use + to add one: a sheet asks for a Name (optional; gray text shows the address an empty name shows) and a URL; type or paste the address (github.com, or github.com/you/project for just that part of the site). Include subdomains under the URL is checked for a new website. Adding an address already listed selects it. Press Return to open the selected websites, like folders: an open tab of each is brought forward, otherwise it opens in a new tab, without asking first. Double-click a website, or right-click it (which selects it) and choose Edit…, to change its name, URL and Include subdomains; its shortcut stays. Right-click also offers Open. An address another website already has is refused, and that website is selected. − removes the selected websites; Shift-click, Command-click and Command-A select several. General contains checkboxes for Enable Clutch, Ask Before Opening, Launch on Login, and Hide Status Bar Icon, and a line that opens the Shelf. Ask Before Opening, under Enable Clutch, is on by default; turn it off and an app shortcut whose app is not running opens the app at once, and a website shortcut with no open tab opens it in a new tab, with no “⎋ Cancel” / “↩ Open” step. Enabling without Accessibility permission first requests the system authorization prompt. General is one centered column of checkboxes, with a divider separating Enable Clutch and Ask Before Opening from Launch on Login and Hide Status Bar Icon, and another above the Shelf line. Under Enable Clutch a gray line says “Use Caps Lock shortcuts.” While Accessibility permission is still missing, a “Grant Accessibility access…” link in the link color takes that line’s place; click it to open Accessibility settings. The gray line returns after permission is granted or enabling is cancelled, and nothing else on the page moves. Reopen Clutch to show Preferences when its menu-bar icon is hidden. Login launch uses the system login-item service on macOS 13 and later, and a user LaunchAgent on macOS 12. Set this after moving the app to its permanent location.

App List shows applications on the left and a clickable shortcut field on the right, styled like Rectangle's: a round-rect field with the shortcut centered, Caps written as ⇪ (for example “⇪M W”), “Record Shortcut” when empty, and ✕ at its right edge to clear the shortcut (the app stays in the list). Use + to add an application and − to remove all selected applications. Shift-click selects a range, Command-click toggles individual applications, and Command-A selects all. The search field in the bottom bar (Command-F) filters the list as you type: an application is shown when its name contains the text, ignoring case and accents. Shortcuts are not searched. Folders and Websites have the same search field. Down or Return moves into the results, and Escape clears the search and returns to the list; Escape in the search field never closes Preferences. When nothing matches, the list says so. Adding, removing and selecting work on the rows shown; adding an application, or choosing one already in the list, clears a search that would hide it. With the list focused, typing a name jumps to that application; shortcut fields take no part in this. Click a shortcut field, then enter the shortcut exactly as you use it: hold Caps, press one to three keys in order (for example M then W), and release Caps (or press Return while still holding Caps) to save it. The field responds as you type: “⇪…” when Caps goes down, then “⇪M…”, “⇪M W…” and “⇪M W E”. Releasing Caps without another key records nothing, and while a field is recording Caps does not toggle Caps Lock. While recording, the field is pressed in, shows “Hold ⇪ to start…”, and has ⎋ at its right edge to cancel (pointing at it shows “Cancel” or “Use Old Shortcut”); keys pressed without Caps are not recorded. Recording needs Clutch to be enabled, since it reads Caps through the same keyboard monitor; while Clutch is off the field shows “Turn on Clutch”. Keys may repeat (Caps + M + M); none can be Space, Tab, Delete or Return (a window action, which takes one key, can use Delete). Command-click or Shift-click on a shortcut field selects rows using the same multi-selection behavior as the rest of the list. Escape cancels. Space and Tab are reserved and cannot be assigned. Assigning a shortcut already in use asks for confirmation and names who would lose it, for example “⇪M W already opens Excel. To use ⇪M W for Word, Excel will lose its shortcut.” Choose Replace or press Enter to transfer it to the selected application; the previous application stays in the list with its shortcut cleared to “Record Shortcut”. Choose Cancel or press Esc to keep all assignments unchanged. Windows uses the App List layout: window actions (Left Half, Right Half, Fill Height · again: Full, Restore, Make Smaller, Make Larger, Center) on the left and the same shortcut field (for example “⇪←”) on the right. Hover over an action for a full description. Click a field, hold Caps, press a key, and release Caps (the field shows “Hold ⇪ to start…”); Escape or ⎋ cancels, and ✕ clears an action's shortcut. Space and Tab are reserved. Every action fits on the page, so the Windows list does not scroll. A key already used by an app or another action asks for confirmation, and the previous owner stays in its list with “Record Shortcut”. Shortcuts are saved across restarts. Restore Defaults brings back ←, →, ↑, ↓, ⌫, − and =, and asks first if that would take a key from an app. All interface labels are in English.

While Preferences is open, Clutch appears in the Dock and Command-Tab. Pressing Caps alone sends the system Caps Lock event without closing Preferences or its chooser sheets. Nothing closes Preferences but the user: shortcuts, the Shelf and the launch confirmation all work with it open, so a shortcut can be tried right after editing it, and a held Caps keeps working as focus moves to another app. The Shelf and the confirmation appear over it and return focus to it when dismissed. Closing Preferences with the close button, Escape, or Command-W hides the Dock icon once no action panel remains and keeps shortcuts running in the background. Open Preferences with Caps + Tab, from the ⇪+ menu, or by reopening Clutch to bring the window and Dock icon back. Quit Clutch (Command-Q) exits the app.

The window is created on demand and released when closed. The app uses one keyboard event tap, with no continuous polling. Authorization polling runs only while waiting for Accessibility access. If macOS pauses the tap because a callback was late, Clutch resumes it immediately. Secure Event Input (password fields, Terminal’s Secure Keyboard Entry) hides key releases from event taps; after such a quiet period Clutch checks the hardware key state once, so a hidden release can neither leave a key swallowed nor turn ordinary typing into Caps shortcuts. Window-cycling Accessibility calls run off the main thread, and hidutil runs only while the tap is not installed. Saved shortcut or folder lists that cannot be read are kept under `Bindings.unreadable` / `Folders.unreadable` and reported instead of being overwritten. If Caps Lock cannot be restored on quit, Clutch offers Quit Anyway. Control + Caps and Option + Caps have no action and do not switch input sources.

Enable Clutch from the ⇪+ menu and allow it under System Settings > Privacy & Security > Accessibility. A rebuilt local app may need to be removed and added to the permission list again, because ad-hoc signatures change on every build. To keep the permission across rebuilds, create a Code Signing certificate once in Keychain Access (Certificate Assistant > Create a Certificate…) and build with `CLUTCH_SIGN_IDENTITY="<certificate name>" ./build.command`.

While enabled, Caps is temporarily mapped to F18; a physical F18 key has the same effect. Pause, exit and sleep restore the previous mapping. Reopen after a crash, or reboot, to recover. Other keyboard remappers or secure-input contexts may interfere.

Run build.command for a locally signed arm64 + x86_64 application (macOS 12+). Run test.command for routing and mapping recovery checks. Real keyboard/indicator behavior still requires authorized desktop testing.

### Investigating native Caps compatibility

Standalone Caps uses one shared state-machine rule in every context, including editing a name, shortcut recording, and launch confirmation. Context controls only chord actions: Caps shortcuts are suppressed in focused editors, recording, and confirmation. Focus changes preserve standalone Caps while cancelling pending chord actions and retaining swallowed key releases. The original report referred to Clutch's folder name editor, not macOS Finder: the editor previously swallowed Caps without replaying it. Standalone Caps is sent to macOS as one short press. Passing routing/encoding tests does not establish full native input-source, indicator, or Caps Lock compatibility.

## Xcode interface previews

Open `Clutch.xcodeproj` in Xcode 15.2 or later. Finish Xcode's first-launch license and component installation if prompted. Select the Clutch scheme and My Mac, then open `Source/Preferences/PreferencesPreview.swift`. Choose Editor > Canvas (Option-Command-Return), and click Resume if needed. Canvas offers General, App List, Folders, Websites, and Windows previews of the actual AppKit content. The native window toolbar is visible when running the app.

Edit `makePreferencesContent()` in `Source/Preferences/AppDelegate+Preferences.swift` to change the interface. Keep the preview file open in a split editor to see updates; Canvas may need Resume after compilation errors or pausing. Canvas includes a visual title bar and toolbar shell using the app's shared tab labels and symbols; macOS draws the native window chrome when the app runs. Previews only display the interface: they do not run application startup, change keyboard mappings, or handle clicks. App List reads existing bindings, falling back to installed example apps.

Use Command-R to test interactions in the real app; the shared scheme opens Preferences automatically. Quit an already running Clutch first so its single-instance protection does not redirect to an older build. The existing `build.command` remains the release build path.

## Source layout

- `Source/main.swift`: application entry point only.
- `Source/App/`: shared coordinator state, application lifecycle, menus, and window focus/cleanup.
- `Source/Keyboard/`: event tap, keyboard gesture state, Caps mapping/recovery, and standalone Caps system-event replay.
- `Source/Applications/`: app bindings, shortcut recording, activation, and launch confirmation.
- `Source/Folders/`: folder models, batch opening and the Folders page list.
- `Source/Shelf/`: the Caps + Space Shelf: `ShelfEntry` / `Shelf` (Foundation-only, covered by the pure tests) hold the entries, their order, the missing-file cleanup and the name/pinyin search; `ShelfPanel` holds the panel, its table and `ShelfListController`; `AppDelegate+Shelf` opens the panel and adds, opens, reveals and removes files.
- `Source/Websites/`: website models and matching (`WebsiteEntry`, `WebsiteAddress`, `WebsiteTabChoice`, Foundation-only and covered by the pure tests), browser tab listing and switching over Apple Events (`BrowserTabs`), the Websites page list, and adding, removing and opening websites.
- `Source/Preferences/`: Preferences window/pages, general options, and Xcode previews.
- `Source/Windows/`: Caps window layout (`WindowLayout` holds the pure geometry and repeat rules; `WindowManager` applies layouts through Accessibility; `WindowShortcutListController` is the Windows page list).
- `Source/Shared/`: reusable list styling, cells and button callbacks, row reordering (`ListOrder`, used by Folders and the Shelf), saved `WindowShortcuts`, persistence, and errors.

`AppDelegate` holds application data and coordinates keyboard and window behavior. `ApplicationListController` owns the application table; `FolderListController` owns the folder table, with its rendering, selection, editing, and drag handling. Shortcut lookup, conflicts, confirmation and assignment for App List, Folders, Websites and Windows live in one place, `AppDelegate+Bindings.swift` (`ShortcutOwner`, `assignShortcut`, `setShortcuts`); shared list code only handles layout and styling. Both the Xcode project and `build.command` compile these files. When adding a Swift source, add it to the Xcode target as well; the command-line build discovers files recursively. `test.command` checks the pure keyboard, mapping, folder and Shelf logic, then runs AppKit list checks without starting the utility or changing keyboard mappings.

Shared behavior is centralized in `failKeyboard` (failure cleanup/reporting), `PreviousFocus` (transient-panel focus restoration), `ListGeometry` (header/body placement), and `ListSelection` (selection and deletion rules). Modal dismissal and outside-click handling remain owned by each panel.
