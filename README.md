# HyperCaps

A lightweight macOS menu-bar app for Caps-based application shortcuts.

HyperCaps was previously named HyperKey. Its application bundle and signing identifier are `local.maxvoid.HyperCaps`, so macOS registers it under its new identity. Existing preferences are copied from `local.maxvoid.HyperKey` on first launch. Quit the old app before opening this version, grant Accessibility access again, and re-enable Launch on Login from the new app. Internal notification, pasteboard, and legacy LaunchAgent identifiers retain their original names for compatibility.

- Press and release Caps alone to send one Caps Lock system-key press to macOS. HyperCaps does not choose or remember input sources, or manage Caps Lock state; macOS handles the event according to system settings. Holding Caps alone still sends one press on release; the original hold duration is not replayed. Releasing a key or modifier that was already down before Caps (for example, the last letter or Shift while typing quickly) does not cancel this press; pressing another key or modifier while Caps is held does. Native input switching and indicator behavior require desktop verification.
- Hold Caps and press Space to open Folders immediately, without switching input sources. The Space press, its repeats, and its release are consumed, so no space is typed, and repeats do not reopen the panel. An ordinary key pressed before Space cancels the gesture, and holding Control, Option, or Command blocks it (Space then types normally). Caps + Command no longer opens Folders. Keys pressed after opening pass through to the panel. The Folders panel uses the launch confirmation’s native rounded window style, with 6-point top padding and the same bottom controls as Preferences and no visible title or traffic-light buttons; drag its background to move it. Use + to add one or more custom folders and − to remove the selected entries from the list. Shift-click selects a range, Command-click toggles individual entries, and Command-A selects all. Right-click a single entry and choose Rename to edit its display name in place; Return saves, Escape cancels, and the actual folder on disk is unchanged. Double-click or press Return to open all selected entries in Finder. Missing folders and folders that fail to open are skipped; failures are reported together after the remaining entries have been attempted. While holding Caps, type a number or letter or use the arrow keys to select, then release Caps to open the selection. Opening with Caps + Space and releasing the keys without further selection input leaves the panel open, regardless of release order. Releasing a Caps navigation chord does not switch input sources; standalone Caps uses the same system replay as every other context. Caps-held navigation keys pass through to the list. Drag selected rows to reorder them together. Holding the mouse button and sweeping across rows does not extend the selection; use Shift-click or Command-click to select multiple rows. The panel and Preferences share the same folder row layout, full paths, path text colors, and selection styling: inset highlights connect adjacent selected rows, with rounded corners only at each group’s ends. App List uses this same selection styling, and all Preferences pages share the panel’s background surface. Preferences adds Name and Path headings. Preferences headers sit outside their scroll views, keeping the separator full-width when scrollbars appear. Columns use fixed widths, with no automatic resizing or draggable header dividers, matching Mos. Preferences reserves a permanent scrollbar allowance. The Folders panel instead fits its columns to the available viewport, reclaiming that space when the scrollbar is hidden. Shortcut headings stay left-aligned while each shortcut control group aligns to its column’s right edge. The first nine panel rows always show an inline ⇪ numbered shortcut beside the path; Caps Lock-1 through Caps Lock-9 select and scroll to the corresponding folder in the current order. While holding Caps Lock, change the selection with another number, letter typing, or the arrow keys. Command is ignored for Caps-held list navigation. Normal Command shortcuts remain available after releasing Caps Lock. Arrow keys also select entries; Escape or Command-W cancels the list and restores focus to the application/window active before opening it. Clicking outside closes the list and keeps focus on the clicked window. Opening Folders alone does not add a Dock icon. Folder paths, display names, and order are saved across restarts. Folders… is also available in the menu while HyperCaps is disabled.
- Caps + an assigned key activates a running application. Window cycling applies to every App List mapping, including newly added apps and reassigned keys. If the mapped app is already frontmost, each deliberate press cycles to its next non-minimized standard window, wrapping after the last window. For example, Caps Lock + F brings Finder forward; press it again to switch to Finder’s next window. You can keep Caps held and tap F repeatedly. Holding F does not automatically cycle. Window cycling uses Accessibility; apps that do not expose standard windows stay focused without switching. If the running app has no open, non-minimized standard window (for example after closing its last window, or when every window is minimized), HyperCaps reopens it the way clicking its Dock icon does, so Finder, Safari, Terminal and similar apps open a new window and AppKit apps restore a minimized one instead of only switching the menu bar. If it is not running, a compact dialog without an icon or buttons asks “Open <application>?”: Escape or Command-W cancels and restores focus to the previously active application, and Return opens it. Clicking outside dismisses the prompt without changing the clicked application’s focus. The shortcut and its repeat/release events are consumed; unassigned keys pass through. Two-key shortcuts work the same way: hold Caps, press the first key, then the second (for example Caps + M + W opens Word). Only Caps has to stay held: the first key can be tapped and released before the second. Order matters (M + W and W + M are different shortcuts). The first key of a two-key shortcut waits instead of acting immediately: if no second key follows, releasing Caps runs that key’s one-key shortcut, if it has one. Tapping the first key again runs its one-key shortcut for the previous tap, so repeated taps still cycle windows. Any other key cancels the wait and is handled normally. Window actions keep precedence, so a window action key cannot start a two-key shortcut.
- On first launch, the App List starts with Finder (Caps + F), Notes (Caps + N), Preview (Caps + P) and Reminders (Caps + R), and Folders starts with Downloads, Desktop, Documents and Applications (Caps + 1–4). Apps or folders that are missing on the Mac are skipped. Once either list has been changed and saved, its defaults are no longer applied, even if it is emptied.
- Caps + arrow keys, −, = and / arrange the focused window of the frontmost application, following Rectangle's layouts. Caps + ← / → snaps it to the left / right half of its display's visible area (below the menu bar, beside the Dock); pressing the same arrow again while the window is still where HyperCaps put it cycles 1/2 → 2/3 → 1/3. Caps + ↑ keeps the window's position and width and fills the display's height; Caps + ↑ on a window that already spans top to bottom (after Caps + ↑, a half-screen layout, or resizing by hand) maximizes it to the whole visible area (this is not macOS full-screen mode). Caps + ↓ restores the frame the window had before its first HyperCaps layout. Caps + / centers the window on its display, keeping its size. Caps + − / = shrinks / grows the window by 30 points in each direction, keeping its center or any edge already touching the screen; growing stays on screen, and shrinking stops at a quarter of the display. You can keep Caps held and tap the keys repeatedly; holding a key does not repeat. Moving or resizing the window by hand starts a new sequence and a new restore point. Windows in native full-screen mode and HyperCaps's own windows are left alone. These are the default keys; each can be changed on the Windows page of Preferences. A key belongs either to one window action or to one app. In the Folders panel, arrows still navigate the list. Layout uses Accessibility off the main thread. Each layout writes only the size or position that actually changes, in an order whose in-between frame stays on screen, so the window redraws once or twice instead of three times; a corrective write follows only if the app did not land on the target. Apps that refuse a size (fixed-size windows, terminal grids) keep their nearest supported size.
- Command-S toggles HyperCaps while its menu or settings are active. It does not override Save in other applications. Command-W closes Settings, including while a shortcut is being recorded.

## Settings

Scrollable lists use standard AppKit scroll views and scrollbars with plain table rows, as in Mos 3.5.0. Row margins and column widths stay fixed when the system switches between overlay and always-visible scrollbars. Tables, clip views, and scroll views reveal one shared active, behind-window tooltip-material backdrop, matching Mos’s transparent list structure. macOS manages scrollbar appearance, layout, and fading according to System Settings > Appearance > Show scroll bars. Scrollbars hide when the content fits. There is no custom thumb drawing or forced scrollbar style.

Preferences uses a fixed content size of 460 × 311 points (exactly the seven Windows rows, without scrolling), with close-only window controls and no resizing or full-screen mode, matching Mos’s window strategy. AppKit handles display scaling. It has four toolbar pages: General, App List, Folders, and Windows. There is no separate tutorial page: App List, Folders, and Windows each have a native round ? help button in their bottom bar. Clicking it shows a small two-column popover, as in Mos: what to press on the left, what it does on the right; clicking again, clicking elsewhere, or Escape closes it. Folders manages the same saved list as the Caps + Space panel, including adding, removing, renaming, multiple selection, opening, and drag reordering. General contains checkboxes for Enable HyperCaps, Launch on Login, and Hide Status Bar Icon. Enabling without Accessibility permission first requests the system authorization prompt. General shows a gray, underlined “Waiting for Accessibility access” link while permission is still missing; click it to open Accessibility settings. The notice disappears after permission is granted or enabling is cancelled. Reopen HyperCaps to show Preferences when its menu-bar icon is hidden. Login launch uses the system login-item service on macOS 13 and later, and a user LaunchAgent on macOS 12. Set this after moving the app to its permanent location.

App List shows applications on the left and a clickable shortcut field (for example “Caps + M + W”) on the right. Use + to add an application and − to remove all selected applications. Shift-click selects a range, Command-click toggles individual applications, and Command-A selects all. Click a shortcut field, then enter the shortcut exactly as you use it: hold Caps, press one key (or two keys in order, for example M then W), and release Caps to save it. The field responds as you type: “Caps + …” when Caps goes down, then “Caps + M + …” and “Caps + M + W”. Releasing Caps without another key records nothing, and while a field is recording Caps does not toggle Caps Lock. While recording, the field shows “Hold Caps + 1 or 2 keys”; keys pressed without Caps are not recorded. Recording needs HyperCaps to be enabled, since it reads Caps through the same keyboard monitor; while HyperCaps is off the field shows “Turn on HyperCaps”. The two keys must differ, and neither can be Space. Command-click or Shift-click on a shortcut field selects rows using the same multi-selection behavior as the rest of the list. Escape cancels. Space is reserved for Caps + Space (Folders) and cannot be assigned. Assigning a key already in use asks for confirmation and names its current application. Choose Replace or press Enter to transfer it to the selected application; the previous application stays in the list with its shortcut cleared to “Click to set”. Choose Cancel or press Esc to keep all assignments unchanged. Windows uses the App List layout: window actions (Left Half, Right Half, Fill Height · again: Full, Restore, Make Smaller, Make Larger, Center) on the left and a clickable shortcut field (for example “Caps + M + W”) on the right. Hover over an action for a full description. Click a field, hold Caps, press a key, and release Caps (the field shows “Hold Caps + a key”); Escape cancels. Space is reserved for Folders. A key already used by an app or another action asks for confirmation, and the previous owner stays in its list with “Click to set”. Shortcuts are saved across restarts. Restore Defaults brings back ←, →, ↑, ↓, −, = and /, and asks first if that would take a key from an app. All interface labels are in English.

While Preferences is open, HyperCaps appears in the Dock and Command-Tab. Pressing Caps alone sends the system Caps Lock event without closing Preferences or its chooser sheets. Activating an assigned application or opening the Folders panel automatically closes Preferences. When Folders or an application launch confirmation takes over from Preferences, the Dock icon stays until that panel closes, avoiding a focus change that would dismiss the new panel. Closing Preferences with the close button, Escape, or Command-W hides the Dock icon once no action panel remains and keeps shortcuts running in the background. Open Settings from the ⇪+ menu or reopen HyperCaps to bring the window and Dock icon back. Quit HyperCaps (Command-Q) exits the app.

The window is created on demand and released when closed. The app uses one keyboard event tap, with no hold timers or continuous polling. Authorization polling runs only while waiting for Accessibility access. If macOS pauses the tap because a callback was late, HyperCaps resumes it immediately. Secure Event Input (password fields, Terminal’s Secure Keyboard Entry) hides key releases from event taps; after such a quiet period HyperCaps checks the hardware key state once, so a hidden release can neither leave a key swallowed nor turn ordinary typing into Caps shortcuts. Window-cycling Accessibility calls run off the main thread, and hidutil runs only while the tap is not installed. Saved shortcut or folder lists that cannot be read are kept under `Bindings.unreadable` / `Folders.unreadable` and reported instead of being overwritten. If Caps Lock cannot be restored on quit, HyperCaps offers Quit Anyway. Control/Option + Caps has no action and does not switch input sources.

Enable HyperCaps from the ⇪+ menu and allow it under System Settings > Privacy & Security > Accessibility. A rebuilt local app may need to be removed and added to the permission list again, because ad-hoc signatures change on every build. To keep the permission across rebuilds, create a Code Signing certificate once in Keychain Access (Certificate Assistant > Create a Certificate…) and build with `HYPERCAPS_SIGN_IDENTITY="<certificate name>" ./build.command`.

While enabled, Caps is temporarily mapped to F18; a physical F18 key has the same effect. Pause, exit and sleep restore the previous mapping. Reopen after a crash, or reboot, to recover. Other keyboard remappers or secure-input contexts may interfere.

Run build.command for a locally signed arm64 + x86_64 application (macOS 12+). Run test.command for routing and mapping recovery checks. Real keyboard/indicator behavior still requires authorized desktop testing.

### Investigating native Caps compatibility

Standalone Caps uses one shared state-machine rule in every context, including Folders selection and rename, shortcut recording, and launch confirmation. Context controls only chord actions: app shortcuts and Caps + Space are suppressed in focused editors, recording, and confirmation; folder navigation applies only to the selection list. Focus changes preserve standalone Caps while cancelling pending chord actions and retaining swallowed key releases. The original report referred to HyperCaps's Folders panel, not macOS Finder: the editor previously swallowed Caps without replaying it. The replay still discards hold duration, so it does not reproduce native long-press behavior. Passing routing/encoding tests does not establish full native input-source, indicator, or Caps Lock compatibility.

Run `./diagnose-caps.command` in Terminal to observe the event path for 90 seconds (Control-C stops early). If observation is denied, grant that terminal Input Monitoring access and rerun. With HyperCaps disabled, open its Folders panel from the menu, select Chinese, rename an entry, and tap Caps; cancel the rename. Enable HyperCaps and repeat the same sequence starting in Chinese. Also compare a held Caps press in each mode. Save the Terminal output for diagnosis. The tool reports Caps/F18 events at HID and session observation points, modifier flags, frontmost application identifiers, and input-source changes. It does not record typed characters or file names and does not post events or modify mappings. `./diagnose-caps.command --self-test` checks event filtering without starting observation.

## Xcode interface previews

Open `HyperCaps.xcodeproj` in Xcode 15.2 or later. Finish Xcode's first-launch license and component installation if prompted. Select the HyperCaps scheme and My Mac, then open `Source/Preferences/PreferencesPreview.swift`. Choose Editor > Canvas (Option-Command-Return), and click Resume if needed. Canvas offers General, App List, Folders, and Windows previews of the actual AppKit content. The native window toolbar is visible when running the app.

Edit `makePreferencesContent()` in `Source/Preferences/AppDelegate+Preferences.swift` to change the interface. Keep the preview file open in a split editor to see updates; Canvas may need Resume after compilation errors or pausing. Canvas includes a visual title bar and toolbar shell using the app's shared tab labels and symbols; macOS draws the native window chrome when the app runs. Previews only display the interface: they do not run application startup, change keyboard mappings, or handle clicks. App List reads existing bindings, falling back to installed example apps.

Use Command-R to test interactions in the real app; the shared scheme opens Settings automatically. Quit an already running HyperCaps first so its single-instance protection does not redirect to an older build. The existing `build.command` remains the release build path.

## Source layout

- `Source/main.swift`: application entry point only.
- `Source/App/`: shared coordinator state, application lifecycle, menus, and window focus/cleanup.
- `Source/Keyboard/`: event tap, keyboard gesture state, Caps mapping/recovery, and standalone Caps system-event replay.
- `Source/Applications/`: app bindings, shortcut recording, activation, and launch confirmation.
- `Source/Folders/`: folder models/order/batch opening, picker UI, and folder management.
- `Source/Preferences/`: settings window/pages, general options, and Xcode previews.
- `Source/Windows/`: Caps window layout (`WindowLayout` holds the pure geometry, repeat rules, and saved `WindowShortcuts`; `WindowManager` applies layouts through Accessibility; `WindowShortcutListController` is the Windows page list).
- `Source/Shared/`: reusable list styling and button callbacks, window shortcuts, and errors.

`AppDelegate` holds application data and coordinates keyboard and window behavior. `ApplicationListController` owns the application table; each folder view has its own `FolderListController` for rendering, selection, rename, and drag handling. Folder actions receive their source table explicitly rather than looking up the focused window. Shortcut conflict confirmation and assignment live in `AppDelegate+Bindings.swift`; shared list code only handles layout and styling. Both the Xcode project and `build.command` compile these files. When adding a Swift source, add it to the Xcode target as well; the command-line build discovers files recursively. `test.command` checks the pure keyboard, mapping, and folder logic, then runs AppKit list checks without starting the utility or changing keyboard mappings.

Shared behavior is centralized in `failKeyboard` (failure cleanup/reporting), `PreviousFocus` (transient-panel focus restoration), `ListGeometry` (header/body placement), `FolderListPresentation` (picker versus preferences settings), and `ListSelection` (selection and deletion rules). Modal dismissal and outside-click handling remain owned by each panel.
