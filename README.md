# HyperKey

A lightweight macOS menu-bar app for Caps-based application shortcuts.

- Press and release Caps alone to switch immediately between a Latin and the last non-Latin input source. Holding Caps alone has no separate action.
- Hold Caps and press Enter (Return or keypad Enter) to open Folders immediately, without switching input sources. Repeats and key releases do not reopen the panel. An ordinary key pressed before Enter cancels the gesture; keys pressed after opening pass through to the panel. The Folders panel uses the launch confirmation’s native rounded window style, with 6-point side and top padding and the same bottom controls as Preferences and no visible title or traffic-light buttons; drag its background to move it. Use + to add one or more custom folders and − to remove the selected entries from the list. Shift-click selects a range, Command-click toggles individual entries, and Command-A selects all. Right-click a single entry and choose Rename to edit its display name in place; Return saves, Escape cancels, and the actual folder on disk is unchanged. Double-click or press Return to open all selected entries in Finder. While holding Caps, type a number or letter or use the arrow keys to select, then release Caps to open the selection. Opening with Caps + Enter and releasing the keys without further selection input leaves the panel open, regardless of release order. Caps release in the list does not switch input sources, and Caps-held navigation keys pass through to the list. Drag selected rows up or down to reorder them together. The panel and Preferences share the same folder row layout, full paths, path text colors, and native rounded selection. Preferences adds Name and Path headings. Name/Path and Application/Shortcut column widths are fixed, with no draggable header dividers. Shortcut headings stay left-aligned while each shortcut control group aligns to its column’s right edge. The first nine panel rows always show an inline ⇪ numbered shortcut beside the path; Caps Lock-1 through Caps Lock-9 select and scroll to the corresponding folder in the current order. While holding Caps Lock, change the selection with another number, letter typing, or the arrow keys. Command is ignored for Caps-held list navigation. Normal Command shortcuts remain available after releasing Caps Lock. Arrow keys also select entries; Escape or Command-W cancels the list and restores focus to the application/window active before opening it. Clicking outside closes the list and keeps focus on the clicked window. Opening Folders alone does not add a Dock icon. Folder paths, display names, and order are saved across restarts. Folders… is also available in the menu while HyperKey is disabled.
- Caps + an assigned key activates a running application. If it is not running, a compact dialog without an icon or buttons asks “Open <application>?”: Escape or Command-W cancels and restores focus to the previously active application (or the Preferences window when testing there), and Return opens it. Clicking outside dismisses the prompt without changing the clicked application’s focus. The shortcut and its repeat/release events are consumed; unassigned keys pass through. The Settings test button uses the same confirmation.
- Command-S toggles HyperKey while its menu or settings are active. It does not override Save in other applications. Command-W closes Settings, including while a shortcut is being recorded.

## Settings

Preferences has four toolbar pages: General, App List, Folders, and About. Folders manages the same saved list as the Caps + Enter panel, including adding, removing, renaming, multiple selection, opening, and drag reordering. General contains checkboxes for Enable HyperKey, Launch on Login, and Hide Status Bar Icon. Enabling without Accessibility permission first requests the system authorization prompt. General shows a gray, underlined “Waiting for Accessibility access” link while permission is still missing; click it to open Accessibility settings. The notice disappears after permission is granted or enabling is cancelled. Reopen HyperKey to show Preferences when its menu-bar icon is hidden. Login launch uses the system login-item service on macOS 13 and later, and a user LaunchAgent on macOS 12. Set this after moving the app to its permanent location.

App List shows applications on the left and Caps + a clickable key field on the right. Use + to add an application and − to remove the selected application. Click a shortcut field and press a key. Escape cancels. Assigning a key already in use asks for confirmation and names its current application. Choose Replace or press Enter to transfer it to the selected application; the previous application stays in the list with its shortcut cleared to “Click to set”. Choose Cancel or press Esc to keep all assignments unchanged. About is intentionally empty. All interface labels are in English.

While Preferences is open, HyperKey appears in the Dock and Command-Tab, including when its window is minimized. Closing Preferences with the close button, Escape, or Command-W hides the Dock icon and keeps shortcuts running in the background. Open Settings from the ⇪+ menu or reopen HyperKey to bring the window and Dock icon back. Quit HyperKey (Command-Q) exits the app.

The window is created on demand and released when closed. The app uses one keyboard event tap, with no hold timers or continuous polling. Authorization polling runs only while waiting for Accessibility access. Control/Option + Caps has no action and does not switch input sources.

Enable HyperKey from the ⇪+ menu and allow it under System Settings > Privacy & Security > Accessibility. A rebuilt local app may need to be removed and added to the permission list again.

While enabled, Caps is temporarily mapped to F18; a physical F18 key has the same effect. Pause, exit and sleep restore the previous mapping. Reopen after a crash, or reboot, to recover. Other keyboard remappers or secure-input contexts may interfere.

Run build.command for a locally signed arm64 + x86_64 application (macOS 12+). Run test.command for routing and mapping recovery checks. Real keyboard/indicator behavior still requires authorized desktop testing.

## Xcode interface previews

Open `HyperKey.xcodeproj` in Xcode 15.2 or later. Finish Xcode's first-launch license and component installation if prompted. Select the HyperKey scheme and My Mac, then open `Source/PreferencesPreview.swift`. Choose Editor > Canvas (Option-Command-Return), and click Resume if needed. Canvas offers General, App List, Folders, and About previews of the actual AppKit content. The native window toolbar is visible when running the app.

Edit `makePreferencesContent()` in `Source/main.swift` to change the interface. Keep the preview file open in a split editor to see updates; Canvas may need Resume after compilation errors or pausing. Canvas includes a visual title bar and toolbar shell using the app's shared tab labels and symbols; macOS draws the native window chrome when the app runs. Previews only display the interface: they do not run application startup, change keyboard mappings, or handle clicks. App List reads existing bindings, falling back to installed example apps.

Use Command-R to test interactions in the real app; the shared scheme opens Settings automatically. Quit an already running HyperKey first so its single-instance protection does not redirect to an older build. The existing `build.command` remains the release build path.
